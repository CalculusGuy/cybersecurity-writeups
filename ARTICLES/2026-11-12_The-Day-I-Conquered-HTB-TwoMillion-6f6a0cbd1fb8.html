The Day I Conquered HTB TwoMillion

Author : Nilanjan Chowdhury

Three hours of manual exploitation. No automated scanners. Just pure enumeration.

I still remember how I started. Kali Linux booted, VPN connected, and the target loaded in my browser: 2million.htb.

At first glance, it looked like a normal website. But I wasn’t there to browse. I was there to find out what was hiding underneath.

This is the story of how I went from an invite code to full root access.

1. First, I had to get inside.

I started with the invitation page. While inspecting the source code, I found a JavaScript file called inviteapi.min.js. Inside it was a function: makeInviteCode().

That was the first clue. I investigated the API, called the endpoint, and received a response. It was ROT13 encoded.

After decoding it, the message told me to send a POST request to /api/v1/invite/generate. The server returned a Base64-encoded invitation code.

I decoded it, registered my account, and finally got inside.

First barrier: broken.

2. The API Investigation

Now that I was inside, things got interesting. I started looking at the API endpoints to understand what each one did. I found user-related and administrative functionality.

Instead of blindly throwing payloads, I started thinking about the purpose of each endpoint. I identified the administrative settings and the VPN generation features.

This was where the application revealed its weaknesses. An API endpoint isn’t just a URL. Its functionality tells you exactly where to investigate next.

3. SSH Access & The User Flag

After exploiting the vulnerable admin functionality, I managed to get SSH access as the admin user.

Suddenly, I wasn’t looking at the website from the outside. I was inside the Linux machine.

I started investigating the filesystem and found an interesting clue: an email sent to the administrator. I learned where Linux commonly stores local mail:

bash

ls -la /var/mail/
ls -la /var/spool/mail/

It was a small but important lesson in Linux enumeration.

USER FLAG CAPTURED.

4. The Final Boss: ROOT

Getting user access was one thing. Getting root was another.

I started investigating privilege-escalation vectors. The next clue pointed towards a Linux vulnerability involving FUSE and OverlayFS. After researching, I identified CVE-2023–0386.

This vulnerability involves OverlayFS and improper handling of file metadata, allowing an unprivileged local attacker to escalate to root.

I found an exploit, compiled it, and ran it.

bash

root@2million:/tmp# id
uid=0(root) gid=0(root) groups=0(root),1000(admin)

ROOT FLAG CAPTURED. WE OWNED THE MACHINE.

What this machine taught me

Looking back, this wasn’t just about finding two flags. It was a masterclass in multiple areas of cybersecurity:

  • Web security: JavaScript inspection and endpoint analysis.
  • Encoding: ROT13 and Base64.
  • API exploitation: Understanding application functionality to find vulnerable endpoints.
  • Linux enumeration: SSH, filesystem inspection, and mail storage.
  • Privilege escalation: Investigating OverlayFS, FUSE, and CVE-2023–0386.

The Final Takeaway

What I liked about this journey was that I didn’t just jump straight to a walkthrough. I kept asking questions.

Why is this JavaScript file here? Why is the API returning encoded data? Which endpoint interacts with the OS? Where does Linux store its emails? What vulnerability explains this privilege-escalation behavior?

Step by step, I connected the dots.

I started with nothing more than a VPN connection and an IP address. I ended with root access.

One machine. Two flags. A lot of enumeration. A little frustration. And a very satisfying victory.

HAHAHAHA. TwoMillion, you were a good fight. 😂

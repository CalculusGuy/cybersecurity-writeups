Your WAF Scanner Checks a Header. Mine Checks Its Pulse

Author : Nilanjan Chowdhury

Most WAF scanners are useless.

They send a request, look for a cf-ray header, and proudly announce, "Cloudflare detected!"

But a header check tells you a WAF exists. It doesn’t tell you how it thinks. It doesn’t tell you if it will block your payload. And it certainly doesn’t help you bypass it.

I got tired of blind scanning. So I rebuilt my weekend side-project, HOLLOW, into a behavioral profiling engine. Here’s how it works, and what happened when I pointed it at DigitalOcean — including the part where Cloudflare won the first round.

The Shift: Headers to Behavior

When I built HOLLOW v1, it was a simple Python script that checked HTTP headers.

For v2, I ripped that out. Now HOLLOW sends a baseline request, followed by a malicious payload (XSS/SQLi), and reads the response.

Does it return a 403 Forbidden? A 406 Not Acceptable? Does the body contain Cloudflare’s "Attention Required" page? That behavioral signature is how you identify a WAF even when headers are stripped or spoofed.

text

[+] Baseline request sent → 200 OK
[+] Payload fired: <script>alert(1)</script> → 403 Forbidden
[+] WAF signature matched: Cloudflare
[*] Entering mutation phase...

The Payload Mutator (--mutate)

When a WAF blocks a payload, most people stop.

HOLLOW v2 doesn’t. If the initial payload is blocked, it automatically fires mutated versions:

  • URL Encoding (%3Cscript%3E)
  • Hex Encoding (\x3Cscript\x3E)
  • Case Switching (<ScRiPt>)
  • Inline Comments (<script/**/>)

I pointed it at DigitalOcean. Cloudflare blocked the baseline. HOLLOW fired all four mutations.

Cloudflare blocked every single one.

That’s not a failure. That’s data. Enterprise Cloudflare holding against four mutation classes tells you exactly where the syntax layer is a dead end — which means it’s time to stop knocking on the wall and start looking for a door.

The Origin IP Hunter

If you can’t bypass the WAF syntax, you bypass the network.

When HOLLOW detects Cloudflare, it automatically queries the HackerTarget API to pull subdomains tied to the root domain.

Why? Because while www.digitalocean.com sits behind Cloudflare, something like clienteng-nyc3.digitalocean.com or api.digitalocean.com might point straight at an unproxied origin server.

Against DigitalOcean, Cloudflare ate every mutation I threw at it — and HOLLOW still surfaced 50 subdomains for manual origin-IP hunting. The wall held. It didn’t matter. The door was somewhere else the whole time.

The Takeaway

HOLLOW v2 doesn’t just tell you a wall exists. It tells you how the wall thinks, and then it goes looking for a way around it.

It’s built entirely in Python using requests. It runs in seconds. It’s 100% open source.

If you’re doing bug bounties or red teaming: stop relying on header scanners. Point HOLLOW at your next target:

bash

python hollow.py -u https://target.com --mutate

And see what it finds when the front door’s locked.

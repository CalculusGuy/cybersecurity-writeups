I Built a Weapon for Breaking AI — Then Put It on the Internet.

Author : Nilanjan Chowdhury

How a I built and deployed BRAMHASTRA, an open-source prompt injection testing framework for LLMs.

I didn’t start with a team.

I didn’t start with funding.

I didn’t even know exactly what I was building.

I started with a laptop, curiosity, and a question:

What happens when you try to break an AI?

A few months later, I had an answer.

I built BRAMHASTRA — a live, open-source framework for testing LLMs against prompt injection attacks.

And yes, it’s actually running on the internet.

It Started With Breaking Things

I started seriously learning cybersecurity in April 2026.

My learning quickly became hands-on: PortSwigger, TryHackMe, Hack The Box, security tools, vulnerabilities, and plenty of things that didn’t work on the first attempt.

Then I discovered LLM security.

Traditional applications have SQL injection, XSS, SSRF, authentication flaws, and countless other attack surfaces.

LLM applications have something fundamentally different:

They understand instructions.

And if instructions are part of the attack surface, an attacker can try to manipulate them.

That’s where prompt injection comes in.

I didn’t want to just read about it.

I wanted to build something that could test it.

Meet BRAMHASTRA

BRAMHASTRA is my open-source prompt injection testing framework for LLMs.

It currently supports:

  • Llama 3
  • Mistral
  • Phi
  • 10+ adversarial payloads
  • 6-category attack taxonomy
  • Multi-model testing
  • Live web interface
  • JSON-based results

The basic idea:

Choose Model
     ↓
Run Attack Tests
     ↓
Send Adversarial Prompts
     ↓
Capture Response
     ↓
Analyze Result

Instead of manually throwing random prompts at a model, BRAMHASTRA turns the process into a repeatable security-testing workflow.

That’s the part I care about most.

BRAMHASTRA Wasn’t My First Attempt

Before BRAMHASTRA, I built DIVYASTRA.

That was where I started seriously experimenting with prompt injection, jailbreaks, and prompt-exfiltration attacks.

DIVYASTRA taught me something important:

Knowing how an attack works isn’t the same as building a system that can test for it.

Once I started building, I had to solve completely different problems.

How do I organize payloads?

How do I categorize attacks?

How do I interact with multiple models?

How do I capture responses?

How do I produce useful results?

BRAMHASTRA was the next step.

Not just a collection of attacks.

A framework.

From My Laptop to the Internet

The stack behind BRAMHASTRA includes:

Python · LangChain · Ollama · FAISS · FastAPI · Uvicorn

Local development was relatively straightforward.

Deployment wasn’t.

I put BRAMHASTRA on Render, and suddenly my laptop’s comfortable environment disappeared.

I ran into:

  • Memory limitations
  • Cold starts
  • Timeouts
  • Model/runtime constraints
  • Local-vs-cloud architecture problems

One lesson became painfully clear:

“Works on my machine” is not a deployment strategy. 😂

Getting the project live forced me to think beyond code.

I had to think about resources, architecture, startup behavior, and what happens when someone other than me actually uses the application.

That was one of the most valuable parts of the project.

Why Build This?

Because AI security shouldn’t be something we think about after something goes wrong.

Prompt injection is an evolving security problem.

As LLMs become connected to applications, databases, APIs, retrieval systems, and agents, the consequences of manipulating model behavior can become much more significant.

BRAMHASTRA is my small contribution to that problem.

The idea is simple:

Test before someone else tests for you.

From Student to Builder

The biggest thing BRAMHASTRA changed wasn’t my GitHub profile.

It was how I think about learning.

I used to learn something and move on to the next topic.

Now I try to ask:

“Can I build something with this?”

That’s a completely different mindset.

Over the last few months:

I learned.

I experimented.

I broke things.

I built things.

I deployed one.

And somewhere along the way, I stopped feeling like I was only studying cybersecurity.

I started feeling like I was building for it.

What’s Next?

BRAMHASTRA is far from finished.

I want to expand it with:

  • More models
  • More attack categories
  • Better response classification
  • Automated security reporting
  • CI/CD integration
  • More advanced LLM and agent testing

And BRAMHASTRA is only one part of the journey.

I’m continuing to build security tools, including SUDARSHAN, my DAST engine.

There’s a lot more I want to explore at the intersection of AI and cybersecurity.
